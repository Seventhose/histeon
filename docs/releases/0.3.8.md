# Histos 0.3.8

- **Le versioni sopravvivono allo spostamento del sito.** All-in-One WP Migration, Duplicator e `wp search-replace` cambiano l'indirizzo del sito anche dentro le versioni di Histos. L'impronta che le protegge non tornava più: «Commit … corrotto: hash non corrispondente», e nel builder pagine vuote (un sito di prova spostato con All-in-One WP Migration a un indirizzo pubblico). Ora l'impronta non dipende dagli indirizzi nelle URL. Le versioni già scritte passano alla nuova impronta in sottofondo.
- **Riparare un sito già spostato.** Un avviso per gli amministratori chiede l'indirizzo di prima: Histos ripara le versioni che differiscono soltanto per quello. Quelle in cui lo spostamento ha unificato http e https si accettano dopo aver controllato le pagine. Anche da riga di comando: `wp xb versions-repair --from=<indirizzo di prima> [--accept]`. Si scrive solo l'impronta, mai il contenuto, e tutto resta nel registro.
- Traduzioni inglesi: 84 frasi delle ultime versioni (importazione, conversione HTML, ricette e variabili del sito) che mancavano.

Provata sui dati di un sito di prova: con uno spostamento simulato in memoria tutte le 1.379 versioni restano leggibili. Con l'indirizzo di prima se ne riparano 1.331 anche nel caso peggiore; le altre 48 avevano sia http sia https.
