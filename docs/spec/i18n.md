# Lingue

Implementazione: `plugin/src/I18n.php`, `editor/src/lib/i18n.ts`, `scripts/i18n.py`. Test: `plugin/tests/Integration/I18nTest.php`, `editor/test/i18n.test.ts`.

Histeon è scritto in italiano ed è disponibile anche in inglese. Chi usa WordPress in italiano vede l'italiano. Con qualsiasi altra lingua si vede l'inglese, a meno che esista una traduzione proprio per quella lingua: chi usa il tedesco o il francese legge l'inglese, non l'italiano. La lingua è quella del profilo dell'utente (Utenti → Profilo → Lingua), oppure quella del sito se il profilo non ne sceglie una.

Vale lo stesso per Histeon CSS, Lingua Bridge, Static Bridge e il tema XB Blank, ognuno con il proprio text domain.

## 1. Lato PHP

I testi usano gettext con il dominio `xb`: `__( 'Impostazioni', 'xb' )`. Le traduzioni sono in `plugin/languages/`:

- `xb-en_US.po` / `.mo`;
- un file JSON `xb-en_US-<md5>.json` per ogni script classico (`assets/editor/*.js`), che lo carica con `I18n::script()` (`wp_set_script_translations`).

`I18n::fallback()` (filtro `load_translation_file`) e `I18n::script_fallback()` (filtro `load_script_translation_file`) danno il file inglese a ogni lingua che non è l'italiano e non ha un file suo.

## 2. Il builder

L'editor Svelte usa `t('Salva')` e `tn('{0} elemento', '{0} elementi', n, n)`. I segnaposto sono `{0}`, `{1}`… e una frase si traduce sempre intera, perché in inglese l'ordine delle parole cambia.

- Il catalogo inglese (italiano → inglese) è diviso in parti in `editor/i18n/en/*.json`.
- La build le unisce in `assets/builder/strings-en_US.json` e in `strings-en_US.js` (`window.xbStrings = {…}`).
- `BuilderScreen`, solo per chi legge in inglese, carica `strings-en_US.js` come script a sé (con il nonce, prima di `builder.js`, versione da `filemtime`): il browser lo tiene in cache come il bundle, mentre la pagina del builder non va mai in cache. `EditorLaunch` manda invece il JSON nella configurazione (`strings`) delle schede di Histeon nell'editor a blocchi, dove `__` è `t`.
- `i18n.ts` legge il catalogo una volta, prima di ogni altro modulo, così anche le etichette definite fuori dai componenti sono tradotte.

Una parola italiana con due significati usa il contesto: `tx('Annulla', 'undo')` → chiave `undo\u0004Annulla` nel catalogo (come `msgctxt` di gettext). Gli snippet hanno una `key` stabile (l'etichetta italiana) per id dei comandi, scorciatoie e icone; la tela si trova con `iframe[data-xb-canvas]`, mai dal titolo tradotto.

Il test `editor/test/i18n.test.ts` estrae ogni testo passato a `t`, `tn` e `__` e fallisce se:

- manca la traduzione;
- la traduzione ha segnaposto diversi;
- c'è un template literal con `${}`.

### Script senza wp.i18n

Il cassetto Histeon CSS (`assets/builder/histos-css/panel.js`, condiviso con il plugin autonomo) è costruito dall'editor: porta con sé i testi inglesi dei suoi sorgenti (`editor/src/histos-css`), scelti al momento della build da `editor/i18n/en`, e il server gli dice solo se usarli (`english`). La barra di revisione per i clienti (`assets/front/review.js`, sulla pagina pubblica) non carica `wp.i18n`: riceve le traduzioni nella sua configurazione (`i18n`), da `Review\Comments::texts()`, dove ogni testo è un `__()` normale.

## 3. Le mappe e i file di WordPress

Le traduzioni dei lati PHP si scrivono in mappe JSON (italiano → inglese), facili da rivedere e da dividere: `plugin/languages/en/*.json`, `theme/fondamenta/languages/en/`, `theme/xb-blank/languages/en/`, e gli equivalenti in Lingua Bridge e Static Bridge. Da lì `scripts/i18n.py` genera i file che WordPress carica.

```bash
# 1. Il catalogo dei testi (wp-cli nel contenitore di sviluppo)
wp i18n make-pot plugin plugin/languages/xb.pot --domain=xb --exclude=vendor,tests,assets/builder,assets/gutenberg,languages
# 2. .po, .mo e JSON degli script dalle mappe; --strict fallisce se manca qualcosa
python3 scripts/i18n.py po plugin/languages/xb.pot plugin/languages/en plugin/languages/xb-en_US.po --strict
# Controllo di una parte mentre si traduce, prima del .pot
python3 scripts/i18n.py check plugin/languages/en plugin/src/Admin/*.php
```

Histeon CSS autonomo: `scripts/i18n-histos-css.sh` prepara gli stessi file del pacchetto (dominio `histos-css`) e usa le mappe di Histeon più `histos-css/languages/en/`.

I file `.po`, `.mo` e `.json` generati si salvano nel repository insieme alle mappe. Le mappe non entrano nei pacchetti.

## 4. Regole per chi scrive testi

- Mai concatenare pezzi di frase: `sprintf( __( 'Pubblicata la release %s', 'xb' ), $v )` con il commento `/* translators: … */`; nel builder `t('Pubblicata la release {0}', v)`.
- Plurali: `_n()` in PHP, `tn()` nel builder.
- Non si traducono:
  - nomi di opzioni, chiavi, codici di errore;
  - CSS, classi, identificatori e sintassi (DSL, Emmet, SCSS);
  - le istruzioni mandate ai modelli di IA;
  - i nomi dei prodotti.
- Il contenuto dei siti (per esempio i testi dei template di XB Blank, come «Pagina non trovata») è contenuto, non interfaccia: lo traduce chi gestisce il sito, anche con Lingua Bridge.
- Un testo nuovo senza traduzione fa fallire il test del builder. Per PHP, `scripts/i18n.py po … --strict` elenca quello che manca.

## 6. Sviluppo e test

Gli stack di sviluppo e di e2e sono in italiano (`WPLANG` in `wp-config.php`, da `dev/up.sh`): i test usano le etichette italiane. La suite di integrazione forza l'italiano nel bootstrap. L'inglese ha i suoi test: `I18nTest` (ripiego e caricamento del `.mo`) ed `e2e/specs/english.spec.ts` (builder e schermate in inglese cambiando la lingua del profilo).
